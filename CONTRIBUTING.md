# Contributing to BrushCue

Thanks for your interest in BrushCue. We are glad you are here and appreciate every report, idea, and fix that helps make BrushCue better.

## What we can accept

BrushCue's core rendering and image-processing engine is proprietary, so we are not accepting pull requests that add new core features or expose new engine functionality.

We do welcome contributions in these areas:

- **Bug fixes** for the public Python package, examples, packaging, and documentation.
- **Documentation improvements** that make existing behavior clearer or easier to use.
- **Example fixes and improvements** that demonstrate currently supported BrushCue APIs.
- **Bug reports** with reproduction steps, expected behavior, actual behavior, and environment details.
- **Feature requests and ideas** so we can understand what would be useful to you and prioritize future work.

If you are unsure whether a change fits, please open an issue before spending time on a pull request.

## Reporting bugs

When filing a bug report, please include as much of the following as possible:

1. The BrushCue package and version you are using (`brushcue` or `brushcue-cpu`).
2. Your operating system, Python version, and GPU/driver details if relevant.
3. A minimal code sample or notebook that reproduces the issue.
4. The input image or asset needed to reproduce the issue, if you can share it.
5. The expected result and the actual result, including any traceback or error output.

Small, reproducible reports are the fastest for us to investigate.

## Requesting features

Feature requests are very welcome, even though we generally cannot accept feature implementation pull requests. Please describe:

- The problem you are trying to solve.
- The API or workflow you wish existed.
- Any example images, outputs, or comparable tools that explain the use case.
- Whether the request is blocking your work or would simply make things easier.

This feedback helps guide BrushCue's roadmap.

## Community guidelines

Please be respectful, constructive, and specific. We want BrushCue's issue tracker to be useful for everyone, whether you are reporting a bug, suggesting an idea, or sending a fix.
